## 🏗️ Architecture Implemented

### 4-Layer Architecture

```
┌────────────────────────────────────────┐
│ 1. HTTP Routes (FastAPI)                │
│    • LeadIngest → validation            │
│    • LeadResponse → serialization       │
│    • Status codes + headers             │
└─────────────┬──────────────────────────┘
              │
┌─────────────▼──────────────────────────┐
│ 2. Services (Business Logic)            │
│    • LeadService (orchestration)        │
│    • ClassificationService (LLM)        │
│    • DeduplicationService (dedup)       │
└─────────────┬──────────────────────────┘
              │
┌─────────────▼──────────────────────────┐
│ 3. Domain Models (No dependencies)      │
│    • Lead class (pure business logic)   │
│    • No HTTP, no DB imports             │
└─────────────┬──────────────────────────┘
              │
┌─────────────▼──────────────────────────┐
│ 4. Persistence (Supabase AsyncClient)   │
│    • PostgreSQL with async driver       │
│    • Connection pooling                 │
│    • Row-Level Security (RLS)           │
└────────────────────────────────────────┘
```

### Database Schema (6 Tables)

```
leads (Core Entity)
├── id: UUID PK
├── email: VARCHAR UNIQUE
├── lead_score: SMALLINT (0-100)
├── status: VARCHAR (new|qualified|disqualified|processing_error)
├── is_duplicate: BOOLEAN
├── original_lead_id: UUID FK (self-reference)
└── Indexes: email, status, lead_score, created_at, is_duplicate

lead_tags (Multi-select)
├── id: UUID PK
├── lead_id: UUID FK → leads
├── tag: VARCHAR (sales_ready|needs_nurture|spam|low_value|high_priority)
└── Constraint: UNIQUE(lead_id, tag)

classification_history (Audit)
├── id: UUID PK
├── lead_id: UUID FK
├── previous_score, new_score
├── previous_status, new_status
└── changed_by, change_reason

duplicate_log (Dedup Audit)
├── id: UUID PK
├── original_lead_id: UUID FK
├── duplicate_lead_id: UUID FK
├── match_type: VARCHAR (email|phone|fuzzy_name)
└── similarity_score: NUMERIC

api_keys (Future Auth)
├── id: UUID PK
├── key_hash: VARCHAR UNIQUE
├── is_active: BOOLEAN
└── expires_at: TIMESTAMP

audit_log (Full Audit Trail)
├── id: UUID PK
├── action: VARCHAR
├── resource_type, resource_id
├── user_id, status (success|failure)
└── details: JSONB

All tables:
✅ Have indexes on common queries
✅ Have timestamps (created_at, updated_at with trigger)
✅ Have RLS enabled for production
✅ Have proper foreign keys with CASCADE
```
